# EXP-27 — omitting 0x05 ERASE_SRAM does NOT break the hardware-SPI wall (BIS-2)

- **Date:** 2026-08-25
- **Unit:** 2C53T bench unit #1
- **Build:** `make guest-config05` (hardware-SPI config, `FPGA_OMIT_05=1`,
  SCOPE_DEBUG_OVERLAY on for the LCD readout)
- **Status:** CLOSED — negative. `0x05` **excluded**. (Nearly logged a false
  positive; caught by reproducibility.)

## 1. Problem

The working bit-bang loader **omits** `0x05 ERASE_SRAM`; the failing
hardware-SPI loader **sends** it. Is `0x05` what poisons hardware-SPI config
entry on the 2C53T? (BIS-2 of the config-transport bisect.)

## 2. Hypothesis

If `0x05` poisons config entry, the hardware-SPI path with it omitted configures:

- **H true →** `CFG` shows `D1` / anchor `A-1` (port closed, Exp L) / a live
  probe-responsive trace.
- **H false →** `CFG:00039020 D0 A0` — the wall, port still open, unconfigured.

## 3. Procedure

`FPGA_OMIT_05` skips the `0x05 00` frame in `fpga_spi3_config_sequence`, so the
prelude is `0x12 INIT_ADDR → 0x15 CONFIG_ENABLE`. Per run: IAP-flash → **true
power cycle** → scope mode → read the LCD `CFG:` line.

**Precondition (the one that bit us): a "true power cycle" is POWER → "Goodbye"
→ UNPLUG USB → replug.** An IAP flash resets the MCU but NOT the FPGA; a POWER
shutdown with USB attached does not drop the FPGA rail either. Only unplugging
USB makes the FPGA go cold.

## 4. Control

- **With-`0x05` baseline, same session:** `guest-configA-gap GAP=0` →
  `CFG:00039020 A0` (EXP-26). This is the wall pole.
- **Anchor `A`** on every read: `A0` = read path valid AND port open/unconfigured.

## 5. Results

| read | FPGA state | CFG | A | interpretation |
|---|---|---|---|---|
| 1st | **not fully cold** (still held earlier coldtrace scope config) | `00000000` | **-1** | Exp L "configured, port closed" — **but it was LEFTOVER coldtrace config, not BIS-2** |
| 2nd | genuinely cold (USB unplugged) | `00039020` | `0` | the wall — BIS-2's true result |

The `A-1 / CFG:00000000` first read is the config-*success* signature and looked
like a breakthrough. It did **not reproduce**: on a genuinely cold FPGA the
no-`0x05` path lands on the identical wall as the with-`0x05` path. The first
read was the FPGA still running the scope design from earlier in the session (an
IAP flash does not power-cycle the fabric), read before it actually went cold.

## 6. Blind spots

- **The near-miss itself:** a stale FPGA state perfectly mimics a positive here,
  because "successfully configured" and "still configured from before" produce
  the same Exp L port-closed reading. Only the cold-cycle + reproducibility
  distinguished them. Single reads on this test are worthless.
- This tests the `0x05` frame only; the electrical waveform (GPIO-vs-AF drive)
  and the part-state legs remain live.

## 7. Conclusion

- **Established:** on a cold FPGA, hardware-SPI config with `0x05` omitted hits
  the same wall (`CFG:00039020 D0 A0`) as with it. Reproduced.
- **Excluded:** `0x05 ERASE_SRAM` as the hardware-SPI-vs-bit-bang differentiator
  (BIS-2). Joins the inter-byte gap (EXP-26) on the excluded list.
- **NOT excluded:** the transport's clock/edge character and GPIO-vs-AF drive
  (BIS-3 waveform component), and the part state (BIS-4). Both need either a
  logic-analyzer wire-diff of bit-bang vs hardware-SPI on the 2C53T, or an
  external SSPI-capable target — which the Tang Nano 9K (QN88) cannot be, since
  its dedicated SSPI SCLK/SI pins are unbonded (see EXP-28).
- **Method note:** the mandatory power cycle for any 2C53T FPGA-state test is
  POWER → "Goodbye" → **unplug USB** → replug. Skipping the unplug leaves the
  fabric configured and every "did it configure?" read is a lie.
