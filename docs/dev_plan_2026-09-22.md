## 0. Invariants carried forward

- **`meter_tx_header_aa55` stays a runtime toggle** until the word table is
  proven on unit #1 with all twelve words. The table and the default flip land
  in one commit, table first. See the 09-12 plan § 0 for why.
- **The 4 Hz meter poll goes out unobeyed** (`fpga_send_cmd_keepalive()`,
  `00 00` header). The meter answers traffic, not commands; an obeyed poll is
  continuous relay actuation. EXP-26.
- **The acquisition loop is a poll on the handover strobe** (EXP-53/54). Do not
  reintroduce "a read starts a capture", a hold read, or a latency-derived
  un-rotation; all three were retired with evidence and the reasons are in
  `docs/devlog/2026-09-22-the-read-is-the-handshake.md`.

## 1. The gaps that matter most

Listed before the sequence, because two of them were invisible in the previous
plan and one of them reframes a catalog entry.

1. **The trigger level has no user control.** Reg `0x08` is bench-proven, the
   boot reconcile writes the UI level, and `fpga scope level` is its one
   writer. But `scope_adjust_trigger_level()` in `scope_state.c` still has
   **zero callers**: no button moves the level, the on-screen marker never
   moves, and a user cannot set the one parameter that decides whether NORMAL
   fires. Reliable triggering is wishlist Tier 1 #1. This is now a UI job with
   measured semantics behind it (the comparator sees the record + 28 on range
   5; draw the marker at code − 28).
2. **Pre-trigger capture is free and unclaimed.** The catalog gap list says
   "unknown whether the FPGA's ring buffer supports it". EXP-53 answered it:
   the trigger sits at mid-record with 512 samples before it. A horizontal
   position control is pure UI over data the record already holds.
3. **The seam for whole-record consumers.** The committed record is one
   continuous 1024-sample segment rotated so the seam sits at the FPGA's write
   pointer, which is 512 samples from the trigger crossing. The display's soft
   trigger already locates the crossing, so the seam is derivable on the MCU
   and the record can be un-rotated. That is the FFT-live S3 item, and it also
   cleans auto-measurements and cursors.
4. **The signal generator is dead in the shipping image.** DDS output shares
   DAC1/PA4 with the CH1 vertical offset, so `guest-coldtrace` has no siggen.
   M1 is "one image that is the whole instrument" and only covers the meter.
   Needs a decision: time-share DAC1 by mode, or accept and say so in the
   release note.
5. **No release in a month.** v0.3.0 was 2026-08-20. Since then: trigger modes,
   CH2 armed at boot, FFT on live data, the meter word table and decoder, the
   acquisition model. The top doc page by traffic is `dfu_mode_guide.md`, so
   arrivals are flashers, and they are flashing a build from before all of it.
6. **No trusted reference on the bench.** Meter S1 → S2 and vertical S3 → S4
   are both blocked on one bench DMM. Still the one purchase worth making.

## 2. Sequence

### 2.1 Close the open bench items on the current image (one session)

- [ ] Flash v6 (`fftlabels_coldtrace_v6.bin`) and read the FFT screen at 0x0E
      with the 1 kHz tone: `3.0Hz` bottom-left, `6.2kHz` bottom-right, dB
      labels down the left edge, no tall DC peak, header `pk 1.0kHz`. Then the
      8 kHz fold at 0x10, header `pk 4.5kHz`. Update the FFT-live catalog row
      ("screen check pending next flash").
- [ ] **Reg `0x02` as polarity select** (trigger-modes S2c). Stock writes
      `02 03` at boot; the FPGA fires on either edge under it (EXP-53 50j).
      Write `02 01` / `02 02` / `02 00` and repeat the 50j level sweep on a
      2 Hz triangle. Falsifier: a value that leaves only one edge triggering.
      Either outcome closes S2c.
- [ ] **Level offset on a second range** (trigger-modes S2a). The +28 was
      measured on range 5 only. Repeat on range 7 (different gain, same
      comparator). Prediction: same 28 if the offset is digital, scaled if it
      is analog. Then hand the offset to the UI marker.
- [ ] **Fold the EXP-54 arms into `scripts/exp22_stability.py`** so the poll
      loop's acceptance (NORMAL at 0x0E/0x10/0x11/0x12, 1 Hz / 4 Hz squares,
      SINGLE 3/3, body floors) is a regression run rather than a one-off. That
      promotes acquisition record integrity and trigger modes to **S3** in one
      commit.

### 2.2 Trigger level and horizontal position in the UI

- [ ] A button path to `scope_adjust_trigger_level()`, which then calls the
      one writer (`fpga scope level` path) so the register and the marker
      cannot diverge. Marker drawn at code − 28 once 2.1 settles the offset.
- [ ] Horizontal position over the 512 pre-trigger samples: a pan of the
      committed record, no FPGA change.
- [ ] Bench acceptance (spec S2 for trigger level): set the level on screen
      above and below a known signal; NORMAL holds above, fires below, and the
      marker sits on the crossing to within the offset tolerance.
- [ ] Cursors S2 rides along: a cursor delta against the same known signal.

### 2.3 Un-rotate the record from the soft-trigger index

- [ ] Compute the seam as (soft-trigger index + 512) mod 1024 and rotate the
      committed record so index 0 is time-first. Fixture from the EXP-53
      npz records (`reverse_engineering/captures/exp53/`), which carry the
      seam at known positions.
- [ ] Acceptance: the whole-record residual against the drive sine drops to
      the body floor at 0x10/0x11/0x12 (EXP-51's `whole_max` metric, now on
      the un-rotated record). Negative control: the metric on the raw record
      keeps the seam.
- [ ] Then FFT-live consumes the un-rotated record (S3), and auto-measurements
      and cursors inherit it.

### 2.4 M1 and v0.4.0

- [ ] **The eight untested meter words** on unit #1: capacitor, diode,
      thermocouple alongside the resistor and cell. One bench cycle. The
      decoder (#35) and word table (#33) have run on unit #2 only.
- [ ] Fold `guest-coldtrace-meter` into the default build.
- [ ] Decide the siggen question (gap 4). Whichever way, the release note says
      what the image does and does not do.
- [ ] **Tag v0.4.0.** Write the note for the DFU-guide population: what
      changed since v0.3.0 in instrument terms (triggering that works, two
      channels, an FFT you can read, a meter that obeys), and what is still
      provisional.

### 2.5 Bench DMM

### 2.6 Honesty items on user-facing buttons

- [ ] **SAVE prints "SAVED #n" without writing anything** (audit P3). The

      say it did not.
- [ ] Auto-measurements S1 → S2: badge volts and seconds against a bench-driven
      signal. Pairs with 2.3, since the badges eat the whole record.
