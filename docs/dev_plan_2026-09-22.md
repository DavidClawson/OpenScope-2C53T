## 1. The gaps that matter most

Listed before the sequence, because two of them were invisible in the previous
plan and one of them reframes a catalog entry.

1. **The trigger level has no user control.** Reg `0x08` is bench-proven, the
   boot reconcile writes the UI level, and `fpga scope level` is its one
   writer. But `scope_adjust_trigger_level()` in `scope_state.c` still has
   **zero callers**: no button moves the level, the on-screen marker never
   moves, and a user cannot set the one parameter that decides whether NORMAL
   fires. Reliable triggering is wishlist Tier 1 #1. This is now a UI job with
   measured semantics behind it (the comparator sees the record + 28 on range
   5; draw the marker at code − 28).
2. **Pre-trigger capture is free and unclaimed.** The catalog gap list says
   "unknown whether the FPGA's ring buffer supports it". EXP-53 answered it:
   the trigger sits at mid-record with 512 samples before it. A horizontal
   position control is pure UI over data the record already holds.
3. **The seam for whole-record consumers.** The committed record is one
   continuous 1024-sample segment rotated so the seam sits at the FPGA's write
   pointer, which is 512 samples from the trigger crossing. The display's soft
   trigger already locates the crossing, so the seam is derivable on the MCU
   and the record can be un-rotated. That is the FFT-live S3 item, and it also
   cleans auto-measurements and cursors.
4. **The signal generator is dead in the shipping image.** DDS output shares
   DAC1/PA4 with the CH1 vertical offset, so `guest-coldtrace` has no siggen.
   M1 is "one image that is the whole instrument" and only covers the meter.
   Needs a decision: time-share DAC1 by mode, or accept and say so in the
   release note.
5. **No release in a month.** v0.3.0 was 2026-08-20. Since then: trigger modes,
   CH2 armed at boot, FFT on live data, the meter word table and decoder, the
   acquisition model. The top doc page by traffic is `dfu_mode_guide.md`, so
   arrivals are flashers, and they are flashing a build from before all of it.
6. **No trusted reference on the bench.** Meter S1 → S2 and vertical S3 → S4
   are both blocked on one bench DMM. Still the one purchase worth making.

### 2.3 Un-rotate the record from the soft-trigger index

- [x] **Partly done 2026-09-22 (`4921553`, v13):** strobed records are rotated
      at the seam `trig_edge_find_seam()` finds (a value step ≥ 2× every other,
      ≥ 6 counts), trigger at index 512. Unit #1: slow triangle 8/8 records
      time-ordered (seam at 0) vs seams at 87–931 with it off; full regression
      15/15. **Not met for fast periodic signals:** 201 Hz sine at 0x10 still
      had an internal phase break in 3/10 records (5/10 off) — the seam can
      fall where the two segments have similar VALUES but different PHASE, and
      a value-step finder cannot see it. The 0x11 comparison was void (the
      phase-break metric read 0 with un-rotation off too).
      **Cause found the same evening:** sample 0 of a read is often a STRAY
      value that fits neither neighbour (13/20 raw records at 201 Hz / 0x10;
      25/204 in the EXP-53/55/56 captures; samples 1023 → 1 are continuous).
      Its two false steps defeated the seam finder's ratio test. v14 added a
      linear-prediction finder and still failed its pre-stated criterion
      (4/10 broken vs 5/10 off) because prediction was fooled the same way.
      Both finders now skip sample 0; on the 20 raw records the seam comes out
      exact on 19 (brute-force truth) and the 20th, seam at index 1, is
      refused. **Answered by EXP-58 the same night:** the read was one byte
      early — "sample 0" was a stale byte and the last sample was never read.
      v16 reads opcode, dummy, stale, then 1024: stray sample 0 on 0/20
      committed records (13/20 on v15), regression 17/17. (Original note:) why sample 0 is stray.
      Framing was already moved to stock's 2-byte discard (2026-08-15); an old
      note says our reads were one byte late. It touches every consumer.
      **v15 on unit #1 (`d0ce0bb`): criterion met** — 201 Hz / 0x10 NORMAL,
      0/10 records with an internal break (control, un-rotation off: 5/10);
      slow triangle 8/8 time-ordered; full regression 17/17 on the rerun.
      The first v15 run failed one record of EDGE falling (`rfffffff`); the
      host check re-found the seam by raw max jump, which after firmware
      un-rotation the internal stray sample can win (selftest now shows it:
      raw picks the stray sample, the 3-median picks the seam). The check was
      fixed and the rerun passed 8/8 falling, but that one frame was not saved,
      so a genuine misclassification is **not excluded** for it; frames are
      now saved (`exp22_trigger_block_v15_frames.npz`). Log: `reverse_engineering/captures/exp54/unrotate_whole_record_2026-09-22.log`.
